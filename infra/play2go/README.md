# Отдельная проверочная копия на Play2Go

Сервер: `31.77.148.136`, каталог `/opt/school21-pool-copy`.
Адрес: `https://pool.31.77.148.136.nip.io` (временный DNS-сервис).
Основа: production commit `59d181058a9d09265931871d5c787e9633834cf0`.

Это отдельный снимок данных, а не синхронизируемая реплика. Vercel, Supabase,
Telegram webhook и задания рабочей платформы остаются без изменений.
Не используйте эту копию для реального учёта до отдельного переключения.

Проверено 08.10.2026: все 24 таблицы совпали по числу строк после восстановления
(51 пользователь, 5 бассейнов, 132 блока расписания, 128 записей на смены).
Вход и девять API-разделов ответили 200; создание/редактирование/удаление
тестового мероприятия прошло успешно, тестовое мероприятие удалено.
Проверен запрет исходящего TCP из API и отсутствие опубликованных портов у
базы/API. Исходные сервисы ВМ сохранились работающими.

Ежедневный backup timer `pool-copy-backup.timer` включён: 05:00–05:05 по Москве.
Он сохраняет PostgreSQL dump и защищённый архив конфигурации с секретами,
проверяет структуру dump и создаёт SHA-256. Архивы доступны только root.
Первый архив также восстановлен в отдельной проверочной базе: 24 таблицы,
51 пользователь и 132 блока; проверочная база после проверки удалена.
Копия дампа и архива конфигурации сохранена на Mac. Это разовое внешнее
копирование, не автоматическая внешняя система резервного копирования.

Код Telegram-бота и интеграций входит в исходники. Бот, webhook, GitHub cron
и выгрузки Google Sheets рабочей платформы не переключаются. Для полного
резервирования production-секретов нужен действующий доступ Vercel CLI;
вход CLI восстановлен 08.10.2026, но Vercel не позволяет экспортировать
13 production-настроек API типа Sensitive (write-only). CLI записал вместо
значений `[SENSITIVE]`; такие заглушки не установлены на ВМ.
Перечень недостающих настроек сохранён в
`secure/integration-settings-status.json` с признаком `complete: false`.
Для резервирования настоящих значений нужны оригинальные секреты из
защищённого хранилища владельца. Не менять/вращать рабочие секреты ради копии.
До этого нельзя считать комплект настроек интеграций полным.

Из read-only API рабочей платформы восстановлены имя бота
`@school21_pool_bot` и исходный адрес webhook. Они сохранены в защищённом
`secure/source-integration-config.json`, без токена бота. Этот файл и перечень
недостающих настроек включаются в ежедневный архив конфигурации.

Четыре локальных `.env` из папки проекта дополнительно сохранены в
`secure/local-project-settings.tar.gz` (600) и включены в backup. Это локальные
настройки, не подтверждённые production-секреты; они не загружаются в контейнеры.
В них нет токена Telegram-бота, а указанный файл Google credentials отсутствует.

Предоставленный владельцем токен отдельно сохранён в `secure/telegram-bot.env`
с правами 600 и включён в защищённые резервные копии. Файл не подключён к
контейнерам: бот и рассылки копии остаются отключены. Проверен только формат
токена, а не его действительность в Telegram. Остальные отсутствующие
production-секреты это не восстанавливает.

Полный tracked source (не только сборка интерфейса) размещён в каталоге
платформы; отдельный архив кода сохраняется в `secure/source-code-*.tar.gz`.
Проверенный Excel-экспорт рабочей платформы сохранён в
`secure/source-export-20261008.xlsx`.
Production-секреты после авторизованного экспорта сохраняются только в
`secure/production-settings.env`, frontend-настройки — в
`secure/frontend-settings.env`, права 600. Эти файлы **не загружаются** в
контейнеры копии; учётные данные рабочей базы не используются копией.
При наличии этих файлов скрипт включает их в защищённый архив конфигурации.

Изоляция только Docker-сетями: `database` и `application` имеют `internal: true`.
База и API не публикуют порты и не имеют исходящего доступа в интернет.
Только Caddy подключён к внешней сети для HTTPS. Открыты TCP 80/443;
UDP 443 существующего VPN не затрагивается. Нет планировщика и токена бота.
Файрвол, SSH, существующие контейнеры и их сети не изменяются.

Запуск/проверка из каталога сервера:

```sh
docker compose -f infra/play2go/compose.yaml ps
docker compose -f infra/play2go/compose.yaml logs --tail=50 backend
```

База — PostgreSQL 17, прикладной пользователь `pool_app` без прав superuser.
Секреты находятся в `infra/play2go/.env` с правами 600 и не входят в Git.
Исходный архив базы в `secure/source-public.dump`, доступ только root.
Не выполняйте `down -v`: это удалит базу копии.

Сборка интерфейса выполняется на Mac, чтобы не перегружать ВМ с 2 ГБ RAM:
`CI=true REACT_APP_API_URL='' npm --prefix frontend run build`.
API-клиент использует тот же домен, на котором открыт интерфейс.

Для резервной копии на ВМ:

```sh
umask 077
docker compose -f infra/play2go/compose.yaml exec -T db \
  pg_dump -U postgres -d pool -Fc --no-owner --no-acl > secure/copy-backup.dump
```

Архив нужно также сохранять вне ВМ; локальный снимок переноса сохранён на Mac
в `backups/play2go-copy/` с ограниченными правами.
