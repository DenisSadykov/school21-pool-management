# Ручные ачивки

Полученные награды доступны только владельцу аккаунта в `/profile?tab=achievements`.
Каталог не показывается пользователям, старые расчётные ачивки остаются выключенными.
Коины, смены, пенальти и правила начислений не меняются. Картинки сохраняются в БД
и автоматически входят в полные pg_dump. Одна награда выдаётся человеку один раз,
сохраняется между бассейнами и при смене ника. Создание не означает выдачу.

## Интерфейсы

- `GET /api/me/achievements`: только награды текущего пользователя, новые первыми.
- `GET /api/achievements/<id>/image`: изображение для получателя или администратора.
- `POST /api/admin/achievements`: только администратор; multipart `key`, `title`, `file`.
  Постоянный ключ: 1–100 латинских строчных букв, цифр и дефисов; название 1–140
  символов; PNG/JPEG/WEBP до 3 МиБ. Повтор с теми же данными возвращает существующую
  ачивку; попытка изменить её содержимое под тем же ключом — 409. Изображение не
  заменяется у ранее награждённых пользователей.
- `POST /api/admin/achievements/<id>/awards`: только администратор; JSON `user_id`,
  необязательный булевый `notify` (по умолчанию false). ID получателя — постоянный
  ID платформы, не Telegram ID. Повтор возвращает существующую выдачу, не меняя
  дату, автора или параметры уведомления. Он не включает задним числом уведомление.

## Выдача по запросу владельца через чат

Отдельной пользовательской формы нет. Оператор использует проверенный SSH и
`compose-live.sh`, не печатает токены и не вызывает Telegram напрямую. Укажите
действующего администратора как автора операции, точный ник получателя и ключ
награды. Без `--apply` команды только проверяют данные. Проверка готовности
Telegram не подтверждает доставку.

В контейнере backend:

```sh
python manage_manual_achievements.py --admin-nick ADMIN create --key AWARD-KEY --title TITLE --image -
python manage_manual_achievements.py --admin-nick ADMIN --apply create --key AWARD-KEY --title TITLE --image -
python manage_manual_achievements.py --admin-nick ADMIN grant --key AWARD-KEY --recipient NICK --notify
python manage_manual_achievements.py --admin-nick ADMIN --apply grant --key AWARD-KEY --recipient NICK --notify
```

В командах создания `-` принимает бинарное изображение на stdin. Используйте один
и тот же ключ при повторе после сетевой ошибки. Для первой команды нужно заменить
`AWARD-KEY` на допустимый строчный ключ. `--notify` добавлять только по явному
запросу. Изменения проходят те же административные API и журнал действий.

Уведомление создаётся атомарно с выдачей, а доставляется существующим минутным
таймером. Проверяются привязка Telegram, разрешение доставки и тихие часы.
Награды относятся к аккаунту, не к текущему бассейну; настройки рассылок конкретного
бассейна их не отменяют. Ошибка отправки не отменяет награду. Для этого типа
уведомлений ошибка и зависшее `processing` переходят в `error`, без автоматического
повтора: Telegram мог принять сообщение до обрыва соединения. Повтор команды
выдачи ничего не переотправляет. Проверяйте статус события и доставки; при
неоднозначности не обещайте доставку и не запускайте повтор вслепую.

## Первый выпуск и откат

После зелёного CI и проверенного свежего бэкапа отдельно выполнить
`backend/migrate_manual_achievements.py` с соседним `achievement_schema.py`
из проверенного коммита и DATABASE_URL текущего backend. Эти файлы можно запускать
из временного административного каталога: они не импортируют приложение, не
меняют старую схему, не создают награды и не отправляют уведомления. Скрипт создаёт
только `manual_achievements` и `user_achievements`, повторный запуск безопасен.

Затем обычный PR → merge → GitHub автодеплой. Проверка схемы в установленном
deploy-smoke автоматически проверит новые зарегистрированные модели. После
публикации дополнительно проверить новую API под владельцем и посторонним
пользователем, анонимный запрет, изображение и вкладку. Настоящую выдачу выполнять
только после успешного выпуска. При откате к прежнему коду таблицы и изображения
сохраняются; обратная миграция с удалением данных не выполняется.
